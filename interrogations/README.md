# Подмодуль допросов (interrogations/)

Один файл на каждого **main_npc**: `interrogations/{character_id}.json`.
Текст вопросов и ответы — инлайн, без внешних ссылок.

## Файл `{character_id}.json`

```json
{
    "character_id": "sailor",
    "name": "Моряк",
    "role": "Моряк",
    "status": "main_npc",
    "initial_attitude": "настороженный, агрессивный",
    "default_reliability": "mixed",
    "base_questions": {
        …
    },
    // общие вопросы для ВСЕХ сценариев
    "scenarios": [
        …
    ]
    // ответы, специфичные для сценария
}
```

### `base_questions`

Общие вопросы-ответы, одинаковые во всех сценариях. **Ни к чему дублировать** их по числу сценариев — вынесены сюда один
раз.
В каждом сценарии `base_questions` подтягиваются автоматически; в `scenarios[].questions` пишется **только отличие**
(override).

### `scenarios[]`

```json
{
    "id": "S12",
    "victim": "tavern_keeper",
    "murder": "sailor",
    "cause": "accident",
    // только для S0X (несчастный случай), иначе отсутствует
    "note": "…",
    // необязательный комментарий
    "true_evidence": [
        "threat_letter",
        "sailor_knife"
    ],
    // улики, повышающие уровень ответа при демонстрации
    "false_evidence": [
        "contraband",
        "cult_items"
    ],
    // улики, понижающие уровень ответа при демонстрации
    "questions": {
        …
    }
    // только вопросы, которые ОТЛИЧАЮТСЯ от base_questions
}
```

Если `questions` пустой — берётся всё из `base_questions`.
Если в `questions` есть ключ (напр. `A6`) — он **замещает** `A6` из `base_questions` в этом сценарии.

### `true_evidence` / `false_evidence`

- **`true_evidence`** — массив ID улик (из `evidence.json`), которые **повышают** уровень ответа при демонстрации.
- **`false_evidence`** — массив ID улик, которые **понижают** уровень ответа при демонстрации.
- Одинаковый вопрос (например `A6`) может быть **общим** в `base_questions`, а ответы — **разными в сценарии** (override
  в `scenarios[].questions`).

## ID сценария

Формат: `S` + 2 цифры d6.

- **Первая цифра — номер жертвы** (bросок d6 по README).
- **Вторая цифра — номер убийцы** (bросок d6).
- **Ведущий `0`** (напр. `S02`, `S03`, …) — **несчастный случай** (убийцы нет, `murder: null`, `cause: "accident"`).

### d6-маппинг (из README)

| Цифра | Персонаж   |
|-------|------------|
| 1     | Трактирщик |
| 2     | Моряк      |
| 3     | Официантка |
| 4     | Врач       |
| 5     | Детектив   |
| 6     | Художник   |

Примеры: `S12` = жертва 1 (Трактирщик), убийца 2 (Моряк). `S02` = жертва 2 (Моряк), несчастный случай. `S25` = жертва 2
(Моряк), убийца 5 (Детектив).

> **Важно:** d6-маппинг (канон) — `1=Трактирщик, 2=Моряк, 3=Официантка, 4=Врач, 5=Детектив, 6=Художник`
> (из главного README, «Механика»). Это НЕ совпадает с порядком `kill_grid._meta.characters`
> (`[sailor, tavern_keeper, waitress, doctor, artist, detective]`). Для ID сценариев **всегда** используйте
> d6-маппинг из главного README, а не порядок `kill_grid`.
>
> **Художник НЕ убивает Моряка** (`kill_grid`: artist→sailor = `alibi`; `murder_matrix`: artist не в `possible_killers`
> Моряка). Поэтому сценария `S26` (жертва Моряк, убийца Художник) не существует — см. `S25` (Детектив).

## Блоки вопросов

| Блок | Тематика                |
|------|-------------------------|
| `A`  | Личность и контекст     |
| `B`  | Что видел/слышал        |
| `C`  | Детали и приметы        |
| `D`  | Хронология и маршруты   |
| `E`  | Проверка и противоречия |
| `F`  | Мотивы и отношения      |
| `Z`  | Финал                   |

### Блок A — 10 вопросов

- **A1** — о себе (имя, как обращаться)
- **A2** — где живёте/работаете
- **A3** — как связаны с таверной/потерпевшим/подозреваемым
- **A4** — где были в **~2:00** (время убийства; из `events.json`, `chapter_4_murder`; не зависит от убитого)
- **A5** — что делали в тот день (по часам)
- **A6** — **о Хозяине таверны** (Гаэтано Вельди). В `base_questions` A6 — ответ на общего; в `scenarios[].questions`
  A6 — **конкретный персонаж** (override).
- **A7** — **об убитом**. В `base_questions` A7 — общий шаблон; в `scenarios[].questions` A7 — **конкретный убитый**
  (override).
- **A8** — **об Официантке** (Виттория Вельди). Override в `scenarios[].questions`.
- **A9** — **о Враче** (Элио Вентури). Override в `scenarios[].questions`.
- **A10** — **о Детективе** (Джакомо Раньери). Override в `scenarios[].questions`.

> **A6–A10 — «о персонаже»** (о каждом НПС, кроме самого допрашиваемого): Хозяин / убитый / Официантка / Врач /
> Детектив.
> В `base_questions` — ответ на общего; в `scenarios[].questions` — override под конкретного персонажа/сценария.
> **A7** — «о убитом» (кто такой). **A6** — «о Хозяине». Оба переопределяются в каждом сценарии.

## Уровни ответов L1–L4

| Уровень | Отношение      | Что даёт                                  | Проверки                    |
|---------|----------------|-------------------------------------------|-----------------------------|
| **L1**  | Неприязнь      | Откровенно лжет или отказывается отвечать | критический провал проверки |
| **L2**  | Обычное        | Очевидный, общеизвестный                  | провал проверки             |
| **L3**  | Малый секрет   | `secret.level: small/medium`              | успех проверки              |
| **L4**  | Большой секрет | `secret.level: big`                       | Критический успех           |

Уровень может подниматься при демонстрации улик или упоминании известных фактов.
Уровень может опускаться при демонстрации ложных улик.

### Улики и уровень ответа

- **Демонстрация улики из `true_evidence`** (материальная или «знание») → **уровень ответа повышается** (L1→L2→L3→L4).
- **Демонстрация улики из `false_evidence`** → **уровень ответа понижается** (L4→L3→L2→L1).
- ID улик — из `evidence.json` (напр. `threat_letter`, `sailor_knife`, `contraband`, `cult_items`).

### Правило «не знаю / соврать»

- **Нет ответа** (уровня нет / `does_not_know`) → персонаж говорит **«не знаю»**.
- **Ответ есть, но доверие/проверка недостаточны** → персонаж либо **врёт**, либо **отвечает «не знаю»**.
- Уровень раскрывается только при достаточном доверии/успехе.

### Правило доверия = 0 → нападёк

- Если **уровень доверия падает до 0** — персонаж **нападает на игрока**.
- Демонстрация `false_evidence` и провалы проверок снижают доверие; при достижении 0 — атака.

## Правила составления

1. **Один файл на персонаж** — `interrogations/{character_id}.json`.
2. **`base_questions`** — общие вопросы (одинаковые для всех сценариев). Пишутся **один раз**.
3. **`scenarios[]`** — только отличия от `base_questions`. Если вопрос не отличается — не дублировать.
4. **ID сценария** — `S` + 2 цифры d6 (жертва/убийца). `S0X` — несчастный случай.
5. **Вопросы и ответы — инлайн**. Без внешних ссылок, без схем, без `questions.json`.
6. **Уровни L1–L4** — по доверию/успеху. L1 — откровенная ложь, L4 — большой секрет.
7. **A6–A10** (о каждом НПС, кроме самого допрашиваемого) переопределяются в каждом сценарии.
8. **Если персонаж не знает** — отвечает «не знаю». Если знает, но доверие недостаточное — врёт или «не знаю».
9. **Можно допрашивать недавно умершего** — через `status: ghost` или `speak_with_dead`.
10. **Улики**: `true_evidence` повышает уровень ответа, `false_evidence` понижает.
11. **Доверие = 0** → персонаж нападёт на игрока.
