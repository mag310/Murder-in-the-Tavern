# v03 — концепт (наброски)

> Рабочий файл: наброски по концепту 3-й версии книги «Убийство в таверне».
> Здесь — идеи и решения для архитектуры сборки, а не готовый текст. После утверждения
> выносим в `README.md` (v03), в `module.md` и в генераторы (`generators/`).
>
> **Ключевой поток (важно):** главы **пишутся в Markdown** (`NN-chapter-N.md`),
> затем **конвертируются в `.typ`** скриптом `generators/md_to_typst.py` и
> **собираются в одну книгу** (`book.typ` → PDF). Авторская форма — `.md`;
> `.typ` — производный артефакт. См. §10.
>
> **Опоры:** `templates.md` (оформление), `pf2e-style/lib.typ` (элементы),
> v02 `murder_book.typ` (что уже собрано), `v01/*` (структура данных).
> Source of truth по данным: `../` (characters/locations/organizations/evidence.json/
> murder_matrix.json/flood_mechanic.json/nightly_beats.json/events.json/interrogations/).

## 1. Архитектура сборки (главное)

v02 — один большой `murder_book.typ` (~4600 строк, ~675 КБ). В v03 — **модульная сборка**:
каждая глава — отдельный `.typ`, общий файл их `#include`, лор — отдельный `.typ` в конце.

```
publication/v03/
  book.typ            # сборочный файл: импорты + include всех глав + include лора
  00-synopsis.md      # титул/логлайн/жанр/концовки (АВТОРСКАЯ форма)  ─┐
  01-chapter-1.md    # Глава 1 — Город (законченный oneshot)          │ .md =
  02-chapter-2.md    # Глава 2 — Таверна и Ночь                       │ что
  03-chapter-3.md    # Глава 3 — Убийство                             │ пишет
  04-chapter-4.md    # Глава 4 — Рассвет                              │ человек
  05-chapter-5.md    # Глава 5 — Потоп                                ─┘
  06-finale.md       # Финал (4 концовки + итоги)
  lore.md            # ВЕСЬ лор (в конце книги)
  ── md_to_typst.py конвертирует каждый *.md → *.typ (ниже, рядом) ──
  00-synopsis.typ   # ПЕРЕВОД (производный; не править руками)
  01-chapter-1.typ  # ПЕРЕВОД (0 ошибок/0 предупреждений при compile)
  ... (01–06 + lore)
  pf2e-style/       # переиспользуемый стиль (junction к ../pf2e-style, см. §10)
```

> **Правило:** правим только `.md`. `.typ` — вывод `md_to_typst.py`, не редактируем
> вручную. Сборка = конвертация всех `.md` → `.typ`, затем `book.typ` их `#include`,
> затем `typst compile book.typ book.pdf` (см. §10).

### 1.1. `book.typ` (сборка)

```typst
#import "pf2e-style/lib.typ": *
#show: pf-stylization
#set page(numbering: "1", ...)

// Обложка / титул
#include "00-synopsis.typ"      // ← из 00-synopsis.md

// Главы (порядок = порядок oneshot'ов; .typ = перевод .md)
#include "01-chapter-1.typ"
#include "02-chapter-2.typ"
#include "03-chapter-3.typ"
#include "04-chapter-4.typ"
#include "05-chapter-5.typ"
#include "06-finale.typ"

// Лор — в самом конце, отдельным блоком
#pagebreak()
#include "lore.typ"            // ← из lore.md
```

> `book.typ` — сам **не** переводится из md: он ручная сборка `#include` переводов
> `.md`. Всё, что внутри глав/лора, — перевод `.md` (см. §10).

### 1.2. Структура одной главы (каждый `NN-chapter-N.typ`)

Каждая глава — **законченный oneshot** (п.1) со своим началом, «телом» и итогами (п.2):

```typst
#chap-header("N", "Название главы", "подзаголовок")

==== Кратко для мастера        // п.5 — краткая инфо на входе в главу
==== Начало (Opening)          // п.2 — своё начало
==== Тело (тело главы)         // п.2 — сцены/локации/NPC/энкаунтеры
==== Итоги (Resolution)        // п.2 — свои итоги (концовки/переход к следующей)
```

> **Отличие v03 от v02:** в v02 лор (Челия, Весткроун, культы) стоит В НАЧАЛЕ книги.
> В v03 лор вынесен В КОНЕЦ (п.4, п.6) — чтобы oneshot-главы читались без предисловия,
> а вся история и заметки собирались в один лорный файл.

## 2. Требования (из задачи)

1. **Каждая глава — законченный oneshot.** Играет отдельно: свой opening → тело → finale.
   Не требует предыдущих глав; не ждёт следующих.
2. **Каждая глава — своё начало, «тело» и итоги.** Три секции (см. 1.2): `Начало` / `Тело` / `Итоги`.
3. **Все главы — в общий typ.** `book.typ` собирает все `NN-chapter-*.typ` через `#include` (см. 1.1).
4. **Весь лор — отдельный файл в конце.** `lore.typ` подключается в конце `book.typ` (п.4).
   Не дублируется по главам.
5. **В начале каждой главы — краткая информация для Мастера.** Секция `==== Кратко для мастера`
   (см. 3) — д6, таймер, что происходит, ключевые улики, DC/СЛ, GM knows.
6. **В лорную часть — полная история приключения + все заметки для Мастера.** `lore.typ`
   (см. 4) — полная история (event_001–021 + timeline) + все GM-заметки + 4 концовки + 6 путей.
7. **Оформление — по `templates.md`.** Шаблоны локации/персонажа/сцены/энкаунтера/божества
   из `../templates.md`; элементы — из `pf2e-style/lib.typ`.

## 3. Краткая информация для Мастера (в начале главы) — п.5

> Единый блок `==== Кратко для мастера` в каждой `NN-chapter-N.typ`. Не дублирует «тело»,
> а даёт Мастеру быстрый старт. Содержит (по мере наличия в данных):

- **Что происходит:** 1–2 предложения (завязка главы).
- **Время главы:** (по `01-chronology.md` / `events.json` `project.timeline`).
- **d6 → персонаж / жертва:** (канон d6-маппинг; `murder_matrix.json`).
- **Ключевые улики главы:** (ID из `evidence.json`, `hidden[].check`/DC из `locations/*.json`).
- **DC/СЛ:** (из `locations/*.json.hidden[].check` + `evidence.json.check`, 2026-10-06).
- **Таймер/потоп:** (если в главе — `flood_mechanic.water_rise`).
- **GM knows / реакция NPC:** (триггеры по раскрытию улик; `characters.*`, `interrogations/`).
- **Итоги/переход:** куда ведёт (к следующему oneshot'у / к finale).

> Источник — `06-quick-reference.md` (v01, расширен 2026-10-06) + `locations.schema.json`
> (`check`/`observation`). Единый формат `check` (`{skill, dc, success, failure}`).

## 4. Лорная часть (в конце книги) — п.4, п.6

`lore.typ` — подключается в конце `book.typ`. **Вся** лорная и GM-информация — здесь,
не по главам. Состав (по `../templates.md` и v02 `murder_book.typ`):

- **Полная история приключения:** предистория event_001–021 + timeline по главам
  (`01-chronology.md §2.2`, `§2.3`; `nightly_beats.json`).
- **Сеттинг:** Челия / Весткроун / река Адивиан / мост (из v02 `murder_book.typ` §1–2).
- **Культы:** Асмодей / Дагон / Сифкеш / Шелин — по `../templates.md` §5 (шаблон божества)
  + `characters/*.json` (deity schema).
- **Все заметки для Мастера:** реакции NPC, триггеры, GM knows (из `characters.*`,
  `interrogations/`, `murder_matrix.special_consequences`).
- **Механика потопа:** 6 путей (`resolution_paths`) + 4 концовки (`endings`) — `flood_mechanic.json`.
- **Быстрые ссылки:** d6, таймер, DC/СЛ, правило трёх улик (из `06-quick-reference.md`).

> **Принцип:** лор — один раз, в конце. Главы на лор **ссылаются** (не копируют), чтобы
> oneshot-глава читалась автономно, а полная история была в одном месте (п.6).

## 9. Центральное преступление (приоритет перед сценами) — п.3, п.6

> Рецензия 2026-10-07: прежде чем писать сцены, зафиксировать **дело / виновника / мотив / три набора улик**.
> Ниже — фиксация по данным `evidence.json` / `characters/*.json`.

### 9.1. Дело, виновник, мотив

- **Центральное преступление главы 1:** **убит культист Дагона** (жертва `random_event_1`, `city_streets`).
  Тело — «мясной куб» (нарезанный ровными кубиками), но это **не «третий за неделю»**, а
  **первое убийство, которое удалось связать с другими** (п.5 рецензии): серия — фон, не задача главы.
- **Виновник (canon):** **Лучиано Аврелиан (Художник, `artist`, d6=6)** — `is_killer:false` по дефолту
  `characters/artist.json`, но как **серийный убийца-паладин/агент ордена из Мендева** (извращённый путь
  по Шелин) — «расправитель над участниками Праздника Пива», значительная часть которых — культисты Дагона
  (`event_010`, `event_018`, `event_020`, `event_031`). *Мастер: в матрице может быть и другой killer
  (`murder_matrix.json`) — канон = Художник.*
- **Истинный мотив:** Художник убивает участников Праздника Пива, считая их негодяями, и «увековечивает»
  их смерть на холсте; ищет украденную **реликвию ордена (мумифицированный череп, `reliquary_skull`)**,
  уверен, что держит один из участников (на деле реликвия в `cult_lair` под алтарём, `event_018`).
- **Что убийца пытался скрыть:** связь серии с культом Дагона + факт, что реликвия у культистов, а не у «участника».

### 9.2. Разбитая улика (п.6 рецензии) — игроки сами складывают «морское»

Кулон-трезубец + перепончатые пальцы **не дают** готовый ответ «Дагон». Разбиваем на 5 частей,
каждая — своя `check` (Внимательность/Мудрость), вывод — из их совокупности:

| Часть | Что видит игрок | DC | Что показывает |
|-------|------------------|----|----------------|
| 1. Кулон | трезубец из кораллов среди нарезки (`trident_pendant`) | Вним. 10 | символ культа (не «морское») |
| 2. Необычные следы | следы нечеловеческих лап к ливневу стоку (`webbed_paw_prints`) | Вним. 10 | что-то нечеловеческое |
| 3. Водяной запах | соля/гниль, «холод с глубины» (atmos) | Мудр./Природа 12 | связь с водой |
| 4. Особенности тела | «мясной куб», ровные срезы (`autopsy_morgue`) | Мудр. 12 | мастерская расчленёнка |
| 5. Свидетель | очевидец / портовый рассказ (`sailor`/`detective`) | Об. 12 | кто-то уходил к реке |

> **Три части** (любых) → «тут явно что-то морское/глубинное» → игроки **сами** выводят культ Дагона.

### 9.3. Три ветки — три типа информации одного дела (п.3, п.12 рецензии)

Одно дело = убийство культиста. Ветки — **способы** его расследовать, не разные приключения:

| Ветка | Игроки узнают | Путь | Ключевые улики (ID `evidence.json`) |
|-------|---------------|------|--------------------------------------|
| **A. Закон** | **КАК** умер | морг → тело → медследы → поддельные заключения | `autopsy_morgue`, `autopsy_reports`, `blood_evidence`, `broken_bottle` |
| **B. Тень** | **ЗАЧЕМ** убили | Совет Воров → наркотики → контрабанда → связь с культом | `contraband`, `devil_bane_crate`, `cult_items`, `rusty_note` |
| **C. Порт** | **КТО** связан с жертвой | Маретти → «Ржавый» → корабль → «Слёзы устрицы» | `black_siren`, `cult_symbol`, `gold_ring`, `webbed_paw_prints` |

- **2 любые ветки → достаточно для разгадки.** 3-я → полная картина + бонус (п.12 рецензии).
- **Таверна не выдана напрямую** (п.4): каждая ветка даёт **факт**, а «Слёзы устрицы» — **вывод**
  из ≥2 веток (см. §9.4). Таверна = эпilogue, не «конечная точка» каждой ветки.

### 9.4. Как рождается «Слёзы устрицы» (вывод, не данность)

```text
       Убийство культиста
          │
   ┌──────┼──────┐
   ▼      ▼      ▼
```

## 10. Поток сборки: md → typ → книга (как это собирается)

> **Главное правило v03:** главы **пишутся в Markdown** (`NN-chapter-N.md`), затем
> **конвертируются в `.typ`** скриптом `generators/md_to_typst.py` и **собираются
> в одну книгу** через `book.typ` → `typst compile` → PDF.
> **Авторская форма = `.md`. `.typ` — производный артефакт, не правится руками.**

### 10.1. Три стадии

```text
  (1) ПИШЕМ       (2) КОНВЕРТИРУЕМ        (3) СБИРАЕМ/КОМПИЛИРУЕМ
  .md  ───────►   md_to_typst.py  ────►   .typ ──► book.typ ──► PDF
  (руками)        (md → typ)             (руками)  (compile)
```

- **(1) ПИШЕМ.** Редактируем только `NN-chapter-N.md` (и `00-synopsis.md`, `lore.md`).
  В `.md` — обычная разметка + fence'ы, которые `md_to_typst.py` понимает.
- **(2) КОНВЕРТИРУЕМ.** `md_to_typst.py <in.md> [<out.typ>]` → `.typ` рядом с `.md`.
- **(3) СБИРАЕМ/КОМПИЛИРУЕМ.** `book.typ` (`#include` всех `.typ`) →
  `typst compile book.typ book.pdf`.

### 10.2. CLI `md_to_typst.py` (факт из `generators/md_to_typst.py`)

- **Один файл:** `md_to_typst.py <in.md> [<out.typ>]` — `.typ` пишется **рядом** с `.md`.
- **Целая книга:** `md_to_typst.py --book [<out.typ>]` — конкатенация
  `00-synopsis + 01-lore + 02-chapter-1 + …` в один `.typ`.
- **Примечание к путям:** конвертер копирует `pf2e-style` рядом с `.typ`
  (`_vendor_pf2e_style`), чтобы `#import "pf2e-style/lib.typ"` и image-path
  (`../../locations/…`) резолвились. Компиляция — `typst compile --root <repo>`.

### 10.3. Что конвертер понимает (md → элементы pf2e-style)

| Markdown | → Typst |
|----------|---------|
| `#### [PF2e stat-block] …` | `#encounter(...)` (PF2e стат-блок) |
| `::: aloud … :::` / `#### Зачитать …` | `#aloud[ … ]` (зачитывать вслух) |
| `::: attention … :::` / `#### Внимание` | `#attention[ … ]` |
| `::: note … :::` / `#### GM knows` | `#note[ … ]` |
| `::: pftab[Имя] … :::` (markdown-таблица) | `#pftab(Имя, …)` (сетка) |
| `::: answers … :::` | `#answers(…)` (допросы L1–L4) |
| `::: figure … :::` | фигура с подписью |
| `> …` | read-aloud |

> **Эскейп:** конвертер экранирует `[`/`]` внутри блоков и не даёт `**bold**`
> распадаться по переносам (это его ключевая защита). Поэтому в `.md` пишем
> `**жирный**` — и не тревожимся о вложенных `[`/`]`/`*`.

### 10.4. Компиляция и валидация (без node)

- `typst` на PATH: `C:\Users\...\typst.exe`.
- v03 — корень проекта `publication/v03/`; `pf2e-style` — junction
  `mklink /J v03\pf2e-style pf2e-style` (или `_vendor_pf2e_style` из конвертера).
- **Проверка:** `typst compile <file>.typ` → **0 ошибок / 0 предупреждений**.
  `01-chapter-1.typ` уже проходит (116 КБ PDF).

### 10.5. Порядок работы при правке главы

1. Правим `NN-chapter-N.md` (контент/DC/улики/сцены).
2. `md_to_typst.py NN-chapter-N.md` → перезаписывает `NN-chapter-N.typ`.
3. `typst compile book.typ` (или отдельный `.typ`) → проверять 0 ошибок/предупреждений.
4. Не правим `.typ` руками — только через `.md` + конвертер.
