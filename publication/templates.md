# Шаблоны оформления блоков приключения

> Единые шаблоны для `v01/masters-book.md`. Каждый блок (локация, персонаж, сцена, энкаунтер и т.д.)
> оформляется по своему шаблону, чтобы глава была единообразной и машинно-читаемой.
> Заполняемый блок = то, что кладётся в masters-book; «Соответствие JSON» = как это поле попадает в
> JSON-source-of-truth.
> `<...>` — заглушка, которую заполняют; `[...]` — опциональный блок (убирают, если не нужен).

---

# 1. Шаблон локации

> Все секции ниже идут **в одинаковом порядке**. Пропущенную опциональную секцию удаляют, не оставляют пустой.

## 1.1. Структура блока (порядок секций)

```
### M.N.O <Название локации> (<Имя на языке лора / англ.>)

#### Зачитать при первом входе в локацию
<3–6 предложений «живого» описания — то, что Мастер читает игрокам голосом.
 Атмосфера + первое, что видят/слышат/чувствуют. Без ссылок на улики.>

#### Атмосфера
<Плотный абзац: что это за место, куда оно вписывается в город/таверну,
 какой контраст создаёт. Ссылка на parent (в какую родительскую зону входит).>

#### Наблюдения
- **<Название наблюдения>** — <что видно>. Условие: осмотр / проверка на <Характеристика> (СЛ <N>).
- **<Название наблюдения>** — <что видно>. Условие: <проверка/знание>.

#### Входы и выходы
- **Вход:** <откуда приходят> (ссылка на локацию/дверь).
- **Выход:** <куда ведут> → <ID/название следующей локации>.
- **Выход (условный):** <только если <условие>>.
- **Секретный вход/выход:** <если есть>.

#### Куда ведёт по расследованию
- **Зацепка → действие → результат → следующая локация** (одна строка на цепочку).
- **Зацепка:** <что узнали/нашли> → **действие:** <что делают> → **результат:** <что получают/узнают> → **следующая локация:** <куда идут>.

#### Зацепки
- **<Название зацепки>** — <что это>. Условие: <как получить>.
- **<Название зацепки>** — <что это>. Условие: <как получить>.

#### Улики
- **<Название улики>** (ID: `evidence_id`) — <что это, что она говорит>. Способ обнаружения: <проверка/обыск> (СЛ <N>).
- **Ложная зацепка (красная сельдь):** <что сбивает, но не блокирует>.

#### Скрытое (при обыске/наблюдении)
- **<Название скрытой детали>** — <что найдут>. Улика: `evidence_id`. Условие: <обыск/наблюдение> (СЛ <N>).

#### NPC
- **<Имя (Роль)>** — <кто, что здесь делает>. См. §2 (персонажи) / [раздел персонажей].

#### История и архитектура
- <Лорный факт про место>.
- <Лорный факт про место>.

#### [События]  (опционально — если в локации есть сцена/энкаунтер)

##### Сцена: <название>
- **Как это работает.** <что происходит, условия>.
- **Атмосфера.** <как это ощущается>.
- **Улики/намёки.** <что заметят при проверке (СЛ N); при критическом успехе — что ещё>.
- **Связь с расследованием.** <как это вписывается в цепочку>.
- **Последствие.** успех → <что получают>; провал → <что происходит>.

#### [Боевая сцена]  (опционально — см. шаблон энкаунтера)

#### GM knows
- <Что знает Мастер, но НЕ игрок>: тайна/секрет локации, что делает NPC, что случится при <условии>.
- **Критическая улика:** <какая улика здесь обязательна и нельзя её потерять из-за одного провала> → <как гарантировать, что игроки её всё равно получат>.
```

## 1.2. Поле-к-полю: мастер-бук ↔ JSON

| Секция в блоке                   | JSON-поле (locations/*.json)                                   | Комментарий                                      |
|----------------------------------|----------------------------------------------------------------|--------------------------------------------------|
| Заголовок / Имя                  | `name`                                                         | Имя + лор-имя в скобках                          |
| (заголовок, тип)                 | `type` (`context`/`gameplay`)                                  | Определяют ли они сцену или только фон           |
| (заголовок, родитель)            | `parent_location`                                              | В какую зону входит                              |
| Зачитать при входе               | — (только для Мастера, не в JSON)                              | Голосовой заход                                  |
| Атмосфера                        | `appearance` + `description`                                   | Визуал + «что это за место»                      |
| Наблюдения                       | `observation` (`{skill, dc, success, failure}`)                | Что видно при осмотре/проверке (с DC/СЛ)        |
| Входы и выходы                   | — (нет поля; связки — в `location_graph.mermaid`)             | Связи; поле `entrances`/`exits` — добавить       |
| Куда ведёт по расследованию      | — (нет поля)                                                   | Цепочка зацепка→действие→результат→локация       |
| Зацепки                          | `clues` (ссылки)                                               | Что дают игроки в расследовании                  |
| Улики                            | `clues` + `hidden[].evidence`                                  | Primary/secondary/false/accident                 |
| Скрытое                          | `hidden[]` (`{description, evidence, check}`)                  | Что найдут при обыске/наблюдении (`check` = DC)  |
| NPC                              | `characters[]`                                                 | Кто здесь                                        |
| История и архитектура            | — (лор, не в JSON)                                             | Фон                                              |
| События                          | `important_events[]`                                           | Сцены/события в локации                          |
| (атмосфера: smell/sound/feeling) | `senses` (`{smell, sound, feeling}`)                           | Сенсорное описание                               |

> **Унификация:** в `locations.schema.json` уже добавлено поле `observation` (`{skill, dc, success, failure}`) и
> `check` у `hidden[]` — так DC/СЛ попадает в JSON и совпадает с master-book. Ещё нет полей `entrances`/`exits`/
> `leads_to` (цепочка зацепка→действие→результат→локация) — связки пока только в `location_graph.mermaid`;
> добавить их при следующем проходе.

# 2. Шаблон персонажа (NPC)

> Два источника стиля: блок NPC в masters-book (раздел «Основные персонажи») и JSON `characters/*.json`
> (через `characters.schema.json`). Шаблоны локации и персонажа — два первых.

## 2.1. Структура блока (порядок секций)

```

- **Имя:** <полное имя>
- **Прозвище:** <если есть>
- **Роль:** <занимаемая в сцене>
- **Раса:** <раса>
- **Мировоззрение:** <PF2e alignment>
- **Статус:** main_npc / context_npc / ghost 
- **Может ли быть жертвой:** true / false

#### Описание
<2–4 предложения «кто это» — профессия, характер, роль в истории.>

#### Внешний вид и черты лица
<Лицо, телосложение, особые приметы. Без ссылок на улики — только то, что видно.>

#### Одежда и детали
<Что одет/носит; заметные предметы.>

#### Поведение и шлейф восприятия
<Как себя ведёт, как реагирует, что заметят при наблюдении.>

#### Речь

 По уровням L1–L4 — см. ниже (не заменяет сами ответы, описывает ПОДАЧУ).>

#### Профессия
- <должность/занятие>
- <доп. роль/тайная роль, если раскрывается>

#### Скрывает
- **[big]** <большая тайна>.
- **[small]** <малая тайна>.
- **Кто знает** (known_by): <ID персонажей, знающих о тайне>.

#### Хочет
- <цель 1>
- <цель 2>

#### Боится
- <страх 1>
- <страх 2>

#### Отношения
- **<Имя (Роль)>** — <тип связи + что это значит>.
- **<Имя (Роль)>** — <тип связи + что это знает/не знает>.

#### [PF2e stat-block]  (опционально — если персонаж/ NPC участвует в бою или нужен для игры)
> См. §4 (шаблон энкаунтера / стат-блока). Единый стандарт: 20-строчная таблица параметров (порядок из §4.1)

> строку; НЕ использовать `Тип`/`Сопротивления`/`Характеристики`/`Снаряжение` вместо стандартных строк.

- **Тайна:** <что Мастер знает, но игрок — нет>.

- **При раскрытии тайны:** <угрожает / признаётся / убегает / атакует>.
```

# 4. Шаблон энкаунтера / бой (внутри локации)

> Единый шаблон для `### [PF2e stat-block]`-блока, который конвертер `generators/md_to_typst.py`
> разбирает в `#pftab`-таблицу (2 колонки: параметр | значение). Блок — это **одна** таблица параметров
> + список способностей. Заголовок над блоком задаёт имя и d6 (`## Стат-блок: <Имя> — <Роль> (d6=N)`).

## 4.1. Структура блока (порядок строк, строго как ниже)

> Порядок строк таблицы — **единый стандарт**: 20 строк в этом порядке. Пропущенную строку удаляют целиком
> (не оставляют пустой), но **никогда не меняют порядок и не переименовывают**. Конвертер идёт по этому
> порядку и не «узнаёт» строки по порядку, а по имени — поэтому переименование (напр. `Тип` вместо `Раса`,
> `Сопротивления` вместо `Роль`) или пропуск строк даёт в PDF неполную/некорректную таблицу.

```
## Стат-блок: <Имя> — <Роль> (d6=<N>)

### [PF2e stat-block]

### <Имя / Название>

![Портрет](<путь>)

**<Уровень> <Мировоззрение> <Размер> <Тип> [<подтипы/трейты>]**  
*<Роль: Soldier / Brute / Controller / Sniper / Solo boss / …>*

**Восприятие** +N; <ночное зрение / сумеречное зрение / нюх и т.п.>  
**Языки** <Общий, …>  
**Навыки** <Атлетика +N, Запугивание +N, …>  
**Стр** +N, **Лов** +N, **Тел** +N, **Инт** +N, **Мдр** +N, **Хар** +N  
**Предметы** <длинный меч, кольчуга, тяжёлый щит, …>

---

**AC** N; **Стойкость** +N, **Реакция** +N, **Воля** +N  
**HP** N; **Иммунитеты** <…>; **Слабости** <…>; **Сопротивления** <…>  
**Скорость** N футов

---

**Ближний бой** `[one-action]` <оружие> +N (<урон>, <тип>; <трейты>)  
**Дальний бой** `[one-action]` <оружие> +N (<урон>, <тип>; <трейты>)  
**Заклинания** <…> **DC** N, **атака** +N

---

**Способности:**

- **<Название> (<англ.>) <тип действия>:** <описание>.
- **<Название> `[reaction]`:** <описание>.
- **<Название> `[free-action]`:** <описание>.
```

## 4.2. Правила оформления (что НЕ делать)

- **Одна строка на параметр.** Не смешивать характеристики в одну строку `Характеристики | Сил N, Лов N, …` —
  каждая из 6 (Сила/Ловкость/Телосложение/Интеллект/Мудрость/Харизма) — **отдельная** строка таблицы (конвертер идёт по
  имени строки; слиянная строка теряется).
- **Не выносить «Способности» в таблицу.** `Способности` — это **отдельный список** под таблицей, а НЕ строка
  таблицы. В табличном виде `Способности` появляется только как строка с **параметром** (напр. `Spell DC 25;
  Spell Attack +17`) — и это НЕ список способностей.
- **Имя/уровень — в заголовке, а не в таблице.** `(d6=N)` в заголовке — это **ID d6**, НЕ уровень персонажа;
  уровень берётся из строки `Уровень` таблицы.
- **Не использовать** `Тип`, `Сопротивления`, `Характеристики`, `Снаряжение`, `Специальные способности`
  вместо стандартных строк. Если у существа нет класса/роли — оставляют строку `Класс`/`Роль`, а значение
  описывают (напр. `Класс | — (нежить)`), а не убирают строку и не ставят `Тип`.
- **Обрыв по переносу строки.** Каждая способность/параметр — **одна** логическая строка. Если в markdown
  способность обрывается на полуслове из-за переноса (`… отбрасывает на 10` / новая строка `футов.`),
  это **баг источника**: конвертер не сливает обрыв — нужно либо писать одной строкой, либо продолжать
  строку без переноса. Продолжение, начинающееся с `-` (напр. `- **Название**:`), — это **новая** способность.
- **Иконки экономики действий** в способностях: `реакция` → `реакция` (или `#R`), `1 действие` → `1 действие`,
  `2 действия` → `2 действия`, `3 действия` → `3 действия`. Конвертер сам подбирает иконку по тексту.

## 4.3. Поле-к-полю: таблица стат-блока ↔ JSON (characters/*.json)

| Строка в таблице          | JSON-поле (characters/*.json)                 | Комментарий                        |
|---------------------------|-----------------------------------------------|------------------------------------|
| Уровень                   | `level`                                       | NPC level (не CR)                  |
| Мировоззрение             | `alignment`                                   | PF2e alignment                     |
| Раса                      | `race`                                        | —                                  |
| Класс                     | `class`                                       | PF2e class                         |
| Роль                      | `building_creatures_role`                     | Soldier/Brute/Spellcaster/Sniper/… |
| Восприятие                | `perception`                                  | `уровень + ранг + WIS`             |
| Языки                     | `languages`                                   | —                                  |
| Навыки                    | `skills[]`                                    | `навык +N`                         |
| Сила/Ловкость/…/Харизма   | `ability_modifiers.{str/dex/con/int/wis/cha}` | —                                  |
| AC                        | `ac`                                          | формула в скобках — комментарий    |
| HP                        | `hp`                                          | по таблице Building Creatures      |
| Скорость                  | `speed`                                       | —                                  |
| Спасброски                | `saves.{fortitude/reflection/will}`           | —                                  |
| Ближний бой / Дальний бой | `melee` / `ranged`                            | `оружие +мод: атака, урон`         |
| Способности (список)      | `abilities[]`                                 | отдельно от таблицы                |

> в `publication/murder/01-lore.md` (§3 «Культы»). `<...>` — заглушка; `[...]` — опциональный блок (убирают, если не
> нужен).

## 5.2. Поле-к-полю: текстовая карточка ↔ JSON

| Секция в карточке            | JSON-поле (characters/*.json, по `deity.schema.json`)                                                                     | Комментарий                                 |
|------------------------------|---------------------------------------------------------------------------------------------------------------------------|---------------------------------------------|
| Заголовок / Имя / Эпитет     | `id`, `name`, `epithet`                                                                                                   | `id` = kebab-case, совпадает с именем файла |
| Статус / природа             | `nature` + `alignment` (мир/план → `realm`)                                                                               | nature: bov/demon_lord/devil_lord/archfey   |
| Сферы интересов              | `spheres_of_interest`                                                                                                     | —                                           |
| Эдикты / Анафема             | `edicts` / `anathema`                                                                                                     | —                                           |
| Мировоззрение последователей | `follower_alignments`                                                                                                     | —                                           |
| Царство                      | `realm` (`{name, plan}`)                                                                                                  | —                                           |
| Союзники / Враги / Отношения | `relationships` (`{allies, enemies, others}`)                                                                             | —                                           |
| Храмы / Верующие             | `temples` / `believers`                                                                                                   | —                                           |
| Живот / цвета / символ       | `sacred_animal` / `sacred_colors` / `symbol`                                                                              | —                                           |
| Связь с Весткроуном          | `westcrown` (`{status, temple_in_city, role_in_ap}`)                                                                      | Роль в «Совете Воров» AP                    |
| Преимущества последователя   | `devotee_benefits` (`{divine_attribute, divine_power, divine_skill, preferred_weapon, domains, alternate_domains, note}`) | По Lost Omens: Gods & Magic                 |
| Заклинания жреца             | `cleric_spells`                                                                                                           | Формат «Имя (Spell) / Закл. N»              |
| Божественное вмешательство   | `divine_intercession` (`{summary, boons{minor/moderate/major}, curses{...}}`)                                             | Опционально (Dagon/Sifkesh — null)          |
| Источник                     | `source`                                                                                                                  | Массив «книга pg. N»                        |

> **Дедупликация:** `characters/<id>.json` — source of truth (все поля); `01-lore.md §3` — текстовая карточка для
> Мастера
> (читается вслух, с атмосферой); в `masters-book` божество — только ссылка/указатель, без дублирования.

## 5.3. Заполнение JSON-карточки

- Файл: `characters/<id>.json`, где `<id>` — kebab-case (напр. `asmodeus.json`, `dagon.json`).
- Валидация: по `characters/deity.schema.json` (draft 2020-12); обязательные поля —
  `id, name, epithet, alignment, domains, source`.
- Пустой шаблон: `characters/deity.template.json` — копировать под `<id>.json` и заполнять.
- Примеры заполненных карточек: `characters/asmodeus.json`, `characters/dagon.json`, `characters/sifkesh.json`,
  `characters/shelyn.json`.
