# Убийство в таверне

Закрытый детективный one-shot для настольной ролевой игры.

Игроки оказываются в изолированной таверне на возвышенности, окружённой паводковой водой. Покинуть таверну невозможно в
течение нескольких дней.

Внутри происходит убийство.

При этом практически у каждого присутствует собственная тайна, мотив для убийства другого персонажа, ложная версия
происходящего или преступление, не связанное с текущим убийством.

Главная задача сценария — не просто определить убийцу, а восстановить сеть отношений, преступлений, заблуждений и улик.

## Файлы проекта

### `characters/` (каталог)

Персонажи сценария. По одному JSON-файлу на персонаж: `characters/<id>.json`.

Содержит (у каждого персонажа):

- `id`, `role`, `status` (main_npc / context_npc / ghost), `name`;
- `race` — расa (напр. человек, полуэльф, аасимар, полурослик); `null` — не определено;
- `alignment` — мировоззрение (PF2e: LG/NG/CG/LN/TN/LE/NE/CE); `null` — не определено;
- `can_be_murder_victim` — может ли персонаж быть жертвой текущего убийства (true для персонажей в таверне, false для
  контекстных вне таверны);
- `ghost` — мертвый персонаж (призрак), действующий в игре, но не живой и не жертва (`can_be_murder_victim: false`,
  например Мёртвая жена);
- малые и большие тайны (`small_secret`, `big_secret`);
- отношения (`love`, `hatred`, `money`, `religion`, `justice`);
- известные сведения (`knowledge`) и ложные убеждения (`false_beliefs`);
- привязку к локациям через расписание дня (`daily_schedule`) и внешние привязки (`external_links`);
- рабочую привязку (`employment`) — на кого/как работает (например, Официантка работает на Трактирщика);
- принадлежность к организациям (`organizations`) — ссылки на `organizations/` (напр. Официантка → tavern, cult);
- для Детектива — секцию `investigation` с нанимателем (`employer: {primary, secondary, alternative}`).

### `characters.schema.json`

JSON Schema для валидации **одного** файла персонажа в каталоге `characters/`.

### `locations/` (каталог)

Все контекстные и игровые локации сценария. По одному JSON-файлу на локацию: `locations/<id>.json`.

Локации разделены на:

- `context` — существуют в истории, но не являются непосредственными игровыми локациями;
- `gameplay` — доступны игрокам непосредственно во время сценария.

Расписание «персонаж → локации» хранится в `daily_schedule` внутри каждого файла персонажа
(`characters/<id>.json`) — см. раздел «Расписание дня».

### `locations.schema.json`

JSON Schema для валидации **одной** локации из каталога `locations/`.

### `organizations/` (каталог)

Организации и группировки сценария. По одному JSON-файлу на организацию: `organizations/<id>.json`.

Каждая организация содержит:

- `id`, `name`, `type`, `description`;
- `members` — список членов: `{character (ID), role, status (active/dead/left), note}`;
- `leader` — ID лидера (или null);
- `location` — ID основной локации (или null);
- `secret` — скрытая природа/цель (или null);
- `conflicts_with` — ID организаций, с которыми эта организация в противостоянии.

Текущие организации:

- `tavern` — «Lacrime della Madreperla» (Слезы устрицы) (business; участники: tavern_keeper, waitress);
- `cult` — Культ Дагона (Dagon, demon — запрещённая ересь в Челии; участники: waitress, doctor, dead_wife);
- `council_of_thieves` — Совет Воров (Council of Thieves) — знаменитый Совет Воров Весткроуна, реальная (тень) власть в
  городе; противоборствует `city_authority`; пока без участников (crime);
- `hellknights` — Адские рыцари (Hellknights) — региональное отделение **Ордена Дыбы (Order of the Rack)** в Весткроуне;
  **факто «Верховный инквизитор» региона** (в Челии нет инквизиции); база — **Цитадель Ривад (citadel_rivad)**;
  **противоборствует `paladin_order`** (`conflicts_with`); участники — **Ликтор (lictor, лидер)**, **Паравикар (
  paravicar)** (order);
- `city_authority` — Городская власть (government; участники: mayor, sheriff; лидер — mayor; противоборствует
  `smugglers`);
- `city_watch` — Городская стража / доттари (government; участник: sheriff; лидер — sheriff; реальная власть — 4
  капитана/дуротасам);
- `paladin_order` — Орден из Мендева (паладины-крестоносцы; покровитель Художника — Шелин, извращённый путь) —
  **Художник — его паладин (тайный агент), НЕ инквизитор**; **противоборствует `hellknights`** (`conflicts_with`); НЕ
  путать с «Орденом чёрной розы» (Cheliax/Asmodeus) (order);
- `smugglers` — Контрабандисты (crime; участники: tavern_keeper, sailor; лидер — tavern_keeper; противоборствует
  `city_authority`);
- `ship_crew` — Экипаж корабля (crew; участники: ship_captain, sailor, doctor (status: left));
- `morgue` — Морговская контора (government; участники: doctor, doctor_assistant); рабочая связь Доктор ↔ Детектив;
- `chelax_bureaucracy` — Бюрократия Челии (House Thrune) (government; противоборствует `paladin_order`).

Ссылка «персонаж → организации» хранится в поле `organizations` внутри каждого файла персонажа (`characters/<id>.json`).

### `organizations.schema.json`

JSON Schema для валидации **одной** организации из каталога `organizations/`.

### `evidence.json`

Улики сценария.

Содержит:

- физические, документальные, поведенческие и другие улики;
- условия обнаружения;
- факты, которые доказывают и не доказают;
- интерпретации персонажей;
- связи с персонажами, локациями, событиями и другими уликами;
- ложные следы.

### `evidence.schema.json`

JSON Schema для валидации `evidence.json`.

### `murder_matrix.json`

Матрицы убийства: по одной на каждого из 6 основных персонажей-жертв (d6). `possible_killers` включает только основных
NPC (не призраков и не контекстных) — призрак (dead_wife) НЕ входит в `possible_killers`, он только улика/призрак, не
убийца.

Содержит:

- `victim` — ID жертвы;
- `possible_killers` — персонажи, способные быть убийцами (только основные NPC);
- `death_causes` — причины смерти (murder, accident, disease, suicide, unknown);
- `required_facts` — факты, необходимые для разрешения дела;
- `required_evidence` — ID улик из `evidence.json`, необходимые для этого сценария;
- `false_leads` — ложные следы, ведущие игрока к неверному подозреваемому;
- `special_consequences` — последствия, если жертва убита именно в этом сценарии.

### `murder_matrix.schema.json`

JSON Schema для валидации `murder_matrix.json`.

### `flood_mechanic.json`

Механика потопа и таймера (Глава 6). Таймер 24 игровых часа, вода прибывает снизу вверх, 6 путей решения, 4 концовки,
принцип «убийство ≠ потоп».

### `nightly_beats.json`

Ежечасные «живые» события: NPC живут своей жизнью по часам (молятся, грузят, убивают, общаются, едят). Таймер тикает по
этим сценам.

# Система тайн

У основных персонажей используется двухуровневая система.

## Маленькая тайна

Преступление, компрометирующий факт или личная особенность, которую персонаж скрывает.

Она не обязательно связана с основным убийством.

## Большая тайна

Ключевой скрываемый факт, способный существенно изменить отношение к персонажу или реконструкцию событий.

Большая тайна также не обязана быть связана с текущим убийством.

## Система знаний

У каждого персонажа есть поле `knowledge` с 4 уровнями знаний:

- `knows_exactly` — точно знает (например, Врач точно знает, что Официантка — верховная жрица);
- `knows_only` — просто знает (например, Трактирщик знает, что Официантка как-то связана с культом, но не знает
  подробностей);
- `suspects` — подозревает (например, Художник подозревает, что Официантка связана с культом, но не уверен);
- `does_not_know` — не знает (например, Моряк ничего не знает о культе в таверне).

Каждый элемент `knowledge` содержит:

- `level` — уровень знания;
- `fact` — текст факта;
- `target` — ID персонажа, о котором известно (или null, если факт не про персонажа);
- `reason` — почему персонаж знает/подозревает (опционально);
- `source` — источник знания: secret, relationship, event, observation, other.

Поле `false_beliefs` содержит ложные убеждения персонажа (то, во что он верит, но что неверно).

Каждое убеждение содержит:

- `belief` — текст убеждения;
- `correctness` — почему убеждение ложное (что реально);
- `source` — источник заблуждения;
- `confidence` — насколько твёрдо персонаж верит (high, medium, low).

# Система отношений

Отношения классифицируются по следующим категориям:

- `love` — любовь, семейная привязанность, романтические отношения;
- `hatred` — личная или кровная ненависть;
- `money` — деньги, работа, торговля, экономические обязательства;
- `religion` — религиозные связи, культ, охота на культистов;
- `justice` — расследование, преступление, наказание, правосудие.

Одна пара персонажей может иметь несколько отношений одновременно.

Например, Трактирщик и Моряк одновременно связаны:

- экономическими отношениями;
- личной ненавистью;
- преступлением из прошлого.

# Мир и лор

## Две страны

Сценарий происходит на границе двух государств с противоположным отношением к демоническому:

- **Город / таверна (Весткроун, Челия)** — страна, где **дьяволопоклонничество Асмодея (Law) — государственная
  религия**, а **демоны (Chaos, в т.ч. Дагон) — запрещённая ересь**. Тайный **культ Дагона** (демон, Chaos) —
  **запрещённая ересь** в этой стране (пытки/казнь).
- **Мендев** — государство, построенное на **борьбе с демонами**; его паладинский орден (paladin_order)
  охотится на культы **демонов (в т.ч. культи Дагона)**.

## Реликвия ордена

Культ Дагона (культа Официантки) украли из ордена **реликвию** — **богато украшенный ковчег, внутри которого лежит
мумифицированный череп святого паладинов**. Ковчег спрятан в логове культа (`cult_lair`) под алтарём (evidence_011).

Орден отправляет в эту страну **Художника** — **паладина** (тайный агент ордена) — для тайной «чистки» культистов
**Дагона** и возвращения
реликвии (event_018, event_020).

## Художник

- **Паладин из МЕНДЕВА (Mendev)** — «Теократии Крестоносцев», государства, которое буквально родилось из войны с
  демонами и граничит с **Мировой Язвой (Worldwound)** — гигантским разломом, из которого изливаются орды демонов.
  Охотящийся на культистов **Дагона** (demon, Chaos — запрещённая ересь; для Мендева это экзистенциальная угроза). Он
  **паладин** (paladin_order), НЕ инквизитор — `paladin_order` и `hellknights` — **две противоборствующие организации**
  (`conflicts_with`).
- **Реликвия украдена из его РОДНОГО храма** — это не просто кража, а военное преступление и святотатство; личная травма
  и провал. Его психика не выдержала.
- **Покровитель — ШЕЛИН (Selyon, богиня искусства/красоты, Neutral Good)**, но его путь — **падение/извращение**: он
  начинал как мирный защитник красоты, видящий «уродство в зле», но в Мендеве столкнулся с уродством в абсолютной,
  демонической форме. Теперь убивая «уродливых» культистов Дагона, он создаёт **идеальную красоту** (их смерть) и
  **увечиечивает её на холсте**; получает **извращённое удовольствие** от убийств, но **не считает себя злодеем**. Он
  перестал защищать красоту и начал **коллеционировать уродство** (его муза — Шелин в её самом тёмном, извращённом
  аспекте; формальный покровитель может быть Рагатиэль/Иомедай).
- **Официально не имеет права на убийства** в этой стране — действует тайно, как **шпион/тайный агент ордена** (см.
  `artist.employment`, `artist.current_murder`).
- **Серийный убийца**: убивает тех, кого считает злыми, и получает от этого удовольствие.
- Его **мотив** — вернуть реликвию и покарать культистов; он **не** убийца текущего дела по умолчанию
  (`is_killer: false`), но может быть `possible_killer` в возможном сценарии.

## dead_wife — бывшая верховная жрица

- dead_wife (мёртвая жена Трактирщика, мать Официантки) **была верховной жрицей культа Дагона** до своей гибели.
- Она **обучила дочь** (Официантку) ритуалам культа при жизни; Официантка **завершила инициацию** после смерти матери
  (event_019).
- Моряк убил dead_wife **не зная, что она — жрица** (считал, что убивает просто жену «коллеги» по криминальным
  делишкам, для запугивания — event_004).
- dead_wife — `ghost` (призрак), обитает у Могилы жены (`wife_grave`), появляется у портрета и у входа к логову культа.

## Город — Весткроун (Westcrown) и река Адиван

- **Весткроун** — «Город Сумерек», бывшая столица Челии; портовый город в устье реки Адиван, ~150 миль к югу от
  Эгориана. Атмосфера упадка, изоляции и тайных культов. Реальная сила — торговля и **Совет Воров (
  council_of_thieves)**, а не городская власть.
- **Таверна — «Lacrime della Madreperla» (Слезы устрицы).** На возвышенности, на берегу реки Адиван. Над воротами висит
  **щит — герб таверны: изображение плачущей морской раковины (оyster, из которой капают «слёзы»)**, вырезанное в тёмном
  дереве/металле, с погнутыми краями и сочащимся мхом. Название и щит — морской/речной мотив (река → море, Дагон).
- **Река Адиван (river)** — регулярно выходит из берегов из-за таяния снегов в горах Менадор. **Потоп = ритуал Дагона +
  естественный паводок** (река → море: влияние Дагона на реки, ведущие к морю).
- **Предшественник:** 4573 AR «Белая Чума» (культ Сифкеш, «Путь Благодати») → создание **Hellknights** (орден, охотится
  на демонических культистов).

# Контекст и игровое пространство

Сценарий использует два типа локаций.

## Context

Локация существует в мире сценария, но игроки не обязаны физически посещать её.

Примеры:

- город;
- места предыдущих убийств;
- корабль.

## Gameplay

Локация непосредственно доступна игрокам.

Примеры:

- двор;
- зал;
- комнаты гостей;
- кабинет Трактирщика;
- подвал;
- логово культа;
- мансарда;
- склад таверны;
- кухня (kitchen);
- морг (morgue, город);

# Расписание дня

У каждого основного персонажа есть `daily_schedule` — расписание дня: в какую часть суток в каком помещении обычно
находится персонаж и что делает.

Части суток (`time`):

- `night` — Ночь (~22:00–04:00);
- `morning` — Утро;
- `day` — День;
- `evening` — Вечер;
- `midnight` — Полночь.

Каждый слот (`scheduleSlot`) содержит:

- `time` — часть суток;
- `location` — ID локации из `locations/`;
- `activity` — что персонаж делает (опционально);
- `note` — пояснение (опционально; напр. тайная смена, возможный сценарий).

Пример (Официантка):

| time     | location      | activity                               |
|----------|---------------|----------------------------------------|
| night    | waitress_room | спит в своей комнате; записи в дневник |
| morning  | cult_lair     | молится в тайной комнате культа        |
| day      | tavern_hall   | обслуживает посетителей в зале         |
| evening  | tavern_hall   | обслуживает посетителей в зале         |
| midnight | cult_lair     | проводит собрание культа               |

Контекстные персонажи (Капитан корабля, Мэр) не имеют расписания внутри таверны (`daily_schedule: null`); для них
указано обычное место через `daily_schedule_note`. **Шериф — активный NPC (`main_npc`), но `daily_schedule: null`**: он
в прологе (город), в таверне не живёт.

Призраки (status: `ghost`, например Мёртвая жена) имеют `can_be_murder_victim: false`, но могут иметь `daily_schedule`
внутри таверны (например, обитание у Могилы жены, появление у портрета, вход к логову культа).

# Призраки

Призраки (status: `ghost`) — это мёртвые персонажи, которые всё ещё действуют в игре. Они:

- имеют `can_be_murder_victim: false` (не могут быть жертвой текущего убийства, как контекстные персонажи);
- могут иметь `daily_schedule` внутри таверны (в отличие от контекстных, у которых `daily_schedule: null`);
- НЕ являются потенциальными жертвами по броску d6 и НЕ входят в 6 основных подозреваемых;
- НЕ входят в `possible_killers` `murder_matrix.json` (призрак — только улика/присутствие, не убийца).

# Модель улик

Улики сценария привязаны к веткам убийства (жертва × убийца/причина смерти) четырьмя ролями:

- `primary` — основная улика: напрямую указывает на убийцу в данной ветке (орудие, мотив, прямой след).
- `secondary` — вспомогательная улика: подводит к основной, создаёт ложные следы, подтверждает мотив/возможность.
- `false` — ложный след: сбивает с толку, но не блокирует расследование.
- `accident` — случайная/не убийственная улика: причина смерти не murder (accident/disease/suicide/unknown) или
  преступление, не связанное с текущим убийством.

Каждая ветка убийства (proof) имеет 1 основную улику + 2–4 вспомогательных. Ложные следы распределены так, чтобы сбивать
с толку, но не блокировать расследование.

Улики могут доказывать текущее убийство: это рабочая модель сценария, где каждая из веток (жертва × убийца/причина
смерти) получает свою основную улику. JSON — рабочая база данных сценария.

# Механика

## Определение жертвы (d6)

Первичная жертва определяется броском d6 в начале приключения.

| Бросок | Жертва     |
|--------|------------|
| 1      | Трактирщик |
| 2      | Моряк      |
| 3      | Официантка |
| 4      | Врач       |
| 5      | Детектив   |
| 6      | Художник   |

Каждый из 6 основных персонажей может быть жертвой (`can_be_murder_victim: true`). Контекстные персонажи (Капитан
корабля, Мэр) не являются потенциальными жертвами (`can_be_murder_victim: false`). **Шериф — активный NPC (
`status: main_npc`), но `can_be_murder_victim: false`**: он в прологе, но НЕ жертва d6 (d6 намеренно 6). Призраки
(status: `ghost`, например Мёртвая жена) не являются потенциальными жертвами (`can_be_murder_victim: false`), но могут
действовать в игре.

> **Заметка по модели `status`:** `main_npc` теперь означает «активный NPC в игре», а не строго «6 d6-жертв». 6 d6-жертв
> (can_be_murder_victim: true) — Трактирщик/Моряк/Официантка/Врач/Детектив/Художник. Шериф — активный NPC, но
> `can_be_murder_victim: false` (не жертва, не подозреваемый).

## Убийства, совершённые NPC

Убийства, совершённые NPC (не связанные с текущим убийством), рассматриваются как *возможные сценарии*, а не канон.

Такие события не являются каноническими, пока не утверждены автором. Они могут быть:

- включены в сценарий (если бросок d6 указал на этого персонажа как жертву);
- исключены из сценария;
- изменены (жертва, мотив, причина смерти).

### Как расследование приводит Детектива в таверну (канон)

Механизм прибытия **определён** (см. `detective.investigation.reason_investigation_reached_tavern`,
`event_023→event_024→event_029`):

1. **Задание (event_023, `sheriff_office`, 15:00):** Шериф нанимает Детектива на поиск **маньяка**, который убивает
   людей по городу и **жестоко расправляется с телами** (расчленение/калечество). 15:15 — гром, начало дождя.
2. **Морг (event_024, `morgue`, 16:00):** Детектив едет в Морг. **Ассистент Доктора (doctor_assistant)** говорит:
   **Доктор забрал ОТЧЁТЫ О ВСКРЫТИИ** и поработает с ними **дома** — снимает комнату в Таверне. Игрокам объясняют
   дорогу. Дождь усиливается.
3. **Ливень (event_029, `tavern_hall`, 19:00):** дождь льёт как из ведра; **Детектив арендует комнату**, чтобы переждать
   дождь → попадает в таверну.

**Улика/артефакт:** `evidence_076` — «Отчёты о вскрытии» в комнате Доктора (`doctor_room`): записи о вскрытиях жертв
маньяка, забранные из Морга. Это объясняет присутствие Доктора в таверне (рабочая задача, не подозрение) и связывает
arrival-mechanic с расследованием. **НЕ дед-улика** текущего убийства (отдельная серия маньяка в городе — принцип «не
любое преступление = убийство»).

# Хронология и таймер (Глава 6)

Сценарий имеет линейную хронологию пролога и таймер потопа. См. `events.json` (`project.timeline`),
`flood_mechanic.json`, `nightly_beats.json`.

## Фазы (`events.json` `project.timeline`)

- `prologue` (Предистория, event_001–event_021) — завершена;
- `chapter_1_city` (Город, 14:00–17:30) — активна;
- `chapter_2_tavern` (Таверна, 17:30–19:00);
- `chapter_3_night` (Ночь, 20:00–2:00);
- `chapter_4_murder` (Убийство, ~2:00);
- `chapter_5_dawn` (Рассвет, 5:45–7:15);
- `chapter_6_flood` (Потоп, таймер 24 часа, 07:15 и далее);
- `finale` (Финал).

## Таймер потопа (`flood_mechanic.json`)

- **Единица** — игровой час; **длительность** — 24 игровых часа после 07:15 (когда река выходит из берегов,
  `event_030`).
- **Привязка** — к сценам/игровым событиям, НЕ к реальному времени. 1 игровой час = 1 завершённая сцена (beat), темп =
  темп Мастера (см. `scene_binding`).
- **Вода прибывает снизу вверх** (`water_rise`): подвал/логово культа → могила/двор → 1 этаж (зал/кухня/кабинет) → 2
  этаж (гостевые комнаты) → мансарда.
- **Принцип «убийство ≠ потоп»**: разгадать убийство и остановить потоп — ДВЕ РАЗНЫЕ задачи (чтобы проклятие Официантки
  не выдавало её как убийцу автоматически, см. `separation_of_concerns`).
- **6 путей решения** (`resolution_paths`): смерть Моряка / смерть Официантки / обратный ритуал Доктора / возврат
  реликвии Художнику / отвязать ялик / утонуть.
- **4 концовки** (`endings`).
