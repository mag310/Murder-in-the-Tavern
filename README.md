# Убийство в таверне

Закрытый детективный one-shot для настольной ролевой игры.

Игроки оказываются в изолированной таверне на возвышенности, окружённой паводковой водой. Покинуть таверну невозможно в течение нескольких дней.

Внутри происходит убийство.

При этом практически у каждого присутствует собственная тайна, мотив для убийства другого персонажа, ложная версия происходящего или преступление, не связанное с текущим убийством.

Главная задача сценария — не просто определить убийцу, а восстановить сеть отношений, преступлений, заблуждений и улик.

---

## Файлы проекта

### `characters.json`

Основной набор персонажей сценария.

Содержит:

- основных NPC;
- контекстных NPC;
- малые и большие тайны;
- отношения;
- связи с правосудием;
- религиозные связи;
- денежные и рабочие связи;
- известные сведения и ложные убеждения;
- привязку персонажей к локациям;
- внешние сюжетные связи;
- `can_be_murder_victim` — может ли персонаж быть жертвой текущего убийства (true для персонажей в таверне, false для контекстных персонажей вне таверны).

### `characters.schema.json`

JSON Schema для валидации `characters.json`.

### `locations.json`

Все контекстные и игровые локации сценария.

Локации разделены на:

- `context` — существуют в истории, но не являются непосредственными игровыми локациями;
- `gameplay` — доступны игрокам непосредственно во время сценария.

### `locations.schema.json`

JSON Schema для валидации `locations.json`.

### `evidence.json`

Улики сценария.

Содержит:

- физические, документальные, поведенческие и другие улики;
- условия обнаружения;
- факты, которые доказывают и не доказают;
- интерпретации персонажей;
- связи с персонажами, локациями, событиями и другими уликами;
- ложные следы.

### `evidence.schema.json`

JSON Schema для валидации `evidence.json`.

### `murder_matrix.json`

Матрицы убийства для каждого из 6 основных персонажей (потенциальных жертв).

Содержит:

- `victim` — ID жертвы;
- `possible_killers` — персонажи, способные быть убийцами;
- `death_causes` — причины смерти (murder, accident, disease, suicide, unknown);
- `required_facts` — факты, необходимые для разрешения дела;
- `required_evidence` — ID улик из `evidence.json`, необходимые для этого сценария;
- `false_leads` — ложные следы, ведущие игрока к неверному подозреваемому;
- `special_consequences` — последствия, если жертва убита именно в этом сценарии.

### `murder_matrix.schema.json`

JSON Schema для валидации `murder_matrix.json`.

# Персонажи

## Основные персонажи

На текущем этапе в таверне находятся шесть основных NPC:

1. Владелец таверны
2. Матрос
3. Дочь владельца
4. Врач
5. Детектив
6. Маньяк

Количество основных подозреваемых намеренно ограничено шестью.

---

## Контекстные персонажи

Контекстные персонажи существуют для формирования истории за пределами таверны.

Текущие:

- Шериф;
- Капитан корабля.

Контекстные персонажи не должны автоматически становиться дополнительными подозреваемыми текущего убийства.

---

# Система тайн

У основных персонажей используется двухуровневая система.

## Маленькая тайна

Преступление, компрометирующий факт или личная особенность, которую персонаж скрывает.

Она не обязательно связана с основным убийством.

## Большая тайна

Ключевой скрываемый факт, способный существенно изменить отношение к персонажу или реконструкцию событий.

Большая тайна также не обязана быть связана с текущим убийством.

---

# Система отношений

Отношения классифицируются по следующим категориям:

- `love` — любовь, семейная привязанность, романтические отношения;
- `hatred` — личная или кровная ненависть;
- `money` — деньги, работа, торговля, экономические обязательства;
- `religion` — религиозные связи, культ, охота на культистов;
- `justice` — расследование, преступление, наказание, правосудие.

Одна пара персонажей может иметь несколько отношений одновременно.

Например, Владелец и Матрос одновременно связаны:

- экономическими отношениями;
- личной ненавистью;
- преступлением из прошлого.

---

# Контекст и игровое пространство

Сценарий использует два типа локаций.

## Context

Локация существует в мире сценария, но игроки не обязаны физически посещать её.

Примеры:

- город;
- офис Шерифа;
- места предыдущих убийств;
- корабль.

## Gameplay

Локация непосредственно доступна игрокам.

Примеры:

- двор;
- зал;
- комнаты гостей;
- кабинет Владельца;
- подвал;
- логово культа;
- чердак.

---

# Принцип проектирования улик

Не следует считать любое обнаруженное преступление доказательством текущего убийства.

Например:

> Игроки находят контрабанду Владельца.

Это доказывает, что Владелец совершает преступление.

Но это не доказывает, что Владелец — убийца.

Аналогично:

> Игроки обнаруживают культ.

Это доказывает существование культа.

Но не доказывает, что культисты убили жертву.

Сценарий должен поддерживать несколько одновременно истинных преступлений.

---

# Незавершённые элементы

Следующие данные пока намеренно не определены:

- имя Владельца;
- имя Матроса;
- имя Дочери;
- имя Врача;
- имя Детектива;
- имя Маньяка;
- имя Шерифа;
- имя капитана;
- название корабля;
- точная личность жертвы текущего убийства;
- кого именно убил Детектив предыдущей ночью;
- почему именно Детектив совершил это убийство;
- каким образом расследование серии смертей привело Детектива в таверну;
- дополнительные связи Матроса;
- дополнительные связи Маньяка;
- содержимое конкретных улик;
- точная механика перемещения между локациями.

`null`, пустые массивы и `status: "needs_definition"` в JSON означают незаполненный элемент сценария, а не утверждённый факт.

# Правило канона

Факт считается каноническим только после явного утверждения автора проекта.

Предложения, появившиеся в процессе обсуждения, но не утверждённые автором, не следует автоматически переносить в канон.

JSON является рабочей базой данных сценария, а не самостоятельным источником новых сюжетных фактов.
