# План доработки сценария «Убийство в таверне»

## 1. Утверждение канона (Story Decisions)

> Оставшиеся решения автора (остальное уже канон).

- [ ] **Личности персонажей** — придумать и вписать имена для 6 основных NPC (Трактирщик, Моряк, Официантка, Врач,
  Детектив, Художник) и для контекстных NPC без имени (Капитан корабля; Мэр = Абериан Арванкси, Ликтор = Ришемар
  Альмансор, Паравикар = Дарсин Ренс, Шериф = Ильтус Мартис — уже заданы).
- [ ] **Название корабля** — придумать и вписать в `characters/sailor.json` / `characters/ship_captain.json`.
- [ ] **Дополнительные связи** — Моряк (помимо дезертирства, кражи казны, убийства жены); Художник (дополнительные
  жертвы/мотивы). Записать в `characters/sailor.json` / `characters/artist.json`.
- [ ] **Таймер 24 часа — реальное или сжатое время** — сейчас `flood_mechanic.timer` = игровые часы, не привязано к
  реальному. Решает автор.

## 2. Наполнение данных (Data Filling)

> Заполнение полей, которые сейчас содержат `null` или `needs_definition`.

- [ ] **Содержимое улик** — пройти по `evidence.json`, заполнить `content`/`description` (текст письма, описание пятна и
  т.д.) и проверить `interpretation` + `false_leads`.
- [ ] **Матрицы убийства** — пройти по `murder_matrix.json`; для каждой жертвы (d6) проверить `false_leads`,
  `required_evidence` (связь с ID из `evidence.json`), `special_consequences`.

## 3. Техническая валидация (Tech Check)

- [ ] **JSON Schema Validation** — валидация всех файлов `characters/`, `locations/`, `organizations/`, `evidence.json`,
  `murder_matrix.json` по их `*.schema.json`.
- [ ] **Согласованность расписаний** — `daily_schedule` всех основных персонажей (нет конфликта `time` + `location`);
  контекстные NPC — `daily_schedule: null` / только `daily_schedule_note`; призраки — `can_be_murder_victim: false`.
- [ ] **Изоляция и локации** — все `gameplay`-локации имеют корректный `parent_location`; игроки не покидают таверну до
  конца.
- [ ] **Статусы жертв** — `can_be_murder_victim: false` у контекстных NPC, Шерифа (`main_npc`) и призраков; они не
  фигурируют как `victim` в `murder_matrix.json`.
- [ ] **Экипаж корабля** — `doctor` имеет `status: left` в `organizations/ship_crew.json` и `characters/doctor.json`.

## 4. Логика (Logic Audit)

- [ ] **Принцип «Не любое преступление = убийство»** — контрабанда/культ/пьянство не автоматически обвиняют в текущем
  убийстве; в `evidence.json` указано, чего они НЕ доказывают.
- [ ] **Логика детектива** — `investigation` не противоречит нанимателю (`primary: sheriff`); `false_beliefs` не
  блокируют расследование.

## 5. Публикация

## 11. Законченный сценарий начала (Opening)

- [ ] **Готовый opening** (не только лор): игроки прибывают → знакомятся с NPC → событие X → таверну отрезает паводком → через N часов находят тело → начинается расследование.
- [ ] **Конкретные сцены начала**: Прибытие → Первое знакомство → Ужин → Сцена конфликта между NPC → Наводнение → Ночь → Обнаружение тела → Первичный осмотр → Первый конфликт между подозреваемыми.
- [ ] **Механизм попадания Детектива в таверну** — утвердить окончательный вариант (сейчас несколько вариантов, решения нет).

## 12. Полноценная структура расследования (game loop)

- [ ] **Game loop**: Игрок → действие → информация → новая гипотеза → следующий доступный шаг.
- [ ] **Что игрок может сделать с каждой уликой** (сейчас есть primary/secondary/false, но недостаточно).
- [ ] **По каждой улике**: способ обнаружения; сложность (DC); необходимые условия; кто может рассказать; можно ли получить несколькими способами; что происходит при провале; какую новую ветку расследования она открывает.

## 13. Система проверки алиби

- [ ] **`daily_schedule` → алиби как механика** (не справочник). Пример: 22:00 убийство; Трактирщик утверждает что в кабинете; Официантка подтверждает, но ненадёжна; Врач видел его в зале в 21:50 → сузить окно времени.
- [ ] **По каждой ветке**: где был убийца; где он утверждает что был; кто может подтвердить; кто врёт; какие физ. доказательства подтверждают/опровергают алиби.

## 14. Формализация временной шкалы (timeline)

- [ ] **Timeline по дням**: День 1 (18:00 прибытие / 19:00 ужин / 21:00 конфликт / 23:10 убийство / 23:30 тело) → День 2 (00:00 расследование / 08:00 завтрак / 10:00 обыск …).
- [ ] **Зависимости событий**: `event_012 requires: evidence_004, time: night_1, location: tavern_hall` (чтобы Мастер не собирал сценарий из JSON вручную).

## 15. Система поведения NPC (behavior layer)

- [ ] **Что хочет NPC** (напр. «не допустить раскрытия культа»).
- [ ] **Что делает, если игроки ничего не делают** (продолжает ритуал).
- [ ] **Что делает, если подозревают** (лжёт → создаёт алиби → уничтожает улику).
- [ ] **Что делает, если раскрыта тайна** (угрожает / признаётся / убегает / атакует).
- [ ] **Реакция при обнаружении тела** (варианты A/B/C по отношению к жертве).

## 16. Система эскалации

- [ ] **Эскалация по таймеру** (паводок как главный таймер, не только сеттинг):
    - 0–6 ч: NPC скрывают секреты;
    - 6–12 ч: начинают уничтожаться улики;
    - 12–24 ч: NPC меняют истории;
    - 24–36 ч: культ проводит ритуал;
    - 36–48 ч: кто-то пытается сбежать;
    - 48+ ч: финальная эскалация.

## 17. Модель «что происходит без игроков» (reactive/living scenario)

- [ ] **T+0** — обнаружено тело; **T+2** — NPC меняют показания; **T+6** — культисты прячут предмет; **T+12** — NPC уничтожает доказательство; **T+18** — появляется призрак; **T+24** — ритуал; **T+36** — NPC пытается сбежать; **T+48** — финальная сцена.

## 18. Условия победы/поражения (win/lose)

- [ ] **Полное раскрытие**: личность убийца + причина + орудие + тело/ключевая улика + опровергнуто алиби.
- [ ] **Частичное раскрытие**: правильный убийца, но не понято мотив.
- [ ] **Ошибка**: обвинён невиновный.
- [ ] **Катастрофа**: убийца сбежал / культ завершил ритуал / уничтожена ключевая улика.

## 19. Финал для каждой ветки (scenario_end_state)

- [ ] Перейти от `special_consequences` к полноценным **end states**: ENDING_A (убийца разоблачён, Трактир спасён, культ раскрыт) / B (разоблачён, но реликвия потеряна) / C (обвинён невиновный) / D (игроки не успели, ритуал завершён) / E (убийца убит игроками, но не понята причина).

## 20. Тексты NPC (dialogue sheets)

- [ ] **Карточка NPC**: Introduction / Personality / Public information / Small secret / Big secret / Lies / Knows / Suspects / Initial attitude / Questions (victim, murder, other NPC, personal secret, location) / Reactions (evidence discovered, accusation, intimidation, secret revealed) / Endgame.

## 21. Handouts (материалы для игроков)

- [ ] Карта таверны; список постояльцев; письмо; дневник; записка; расписание; карта корабля; документы; символ культа; изображение реликвии; портреты NPC; карта расследования.
- [ ] **Физические улики** для игроков (что держат в руках).

## 24. Генератор/валидатор сценария

- [ ] **`validate_scenario.py`**: существует ли каждый referenced character/location; нет ли циклических зависимостей; у каждой ветки есть необходимая улика; у каждого убийцы есть мотив; у каждой жертвы есть death scenario; все события имеют условия; нет недостижимых событий; нет невозможных к получению улик; нет NPC, которые должны знать факт, но не имеют knowledge; нет конфликтующих facts.

## 25. «Машина сценария» (scenario_state)
